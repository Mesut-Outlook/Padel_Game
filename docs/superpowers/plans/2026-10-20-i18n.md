# UI Languages (8) — Plan

**Goal:** The game UI in English, German, Spanish, Turkish, French, Italian, Portuguese and Dutch. The language is picked in Settings; the default follows the browser, then English.

**Why these 8:** they are the padel markets. Spain is ~29% of FIP circuit players, then Argentina, Italy and Portugal; France builds the most new courts. KorrPadel ships a similar set (EN DE ES FR IT NL PT-BR SV). Turkish is the owner's own market. Research notes: conversation of 2026-10-20.

**Cost:** ~700–1000 UI strings, 20–35 KB of text. Each language is a separate lazy chunk of ~8–12 KB gzip; only the chosen one is downloaded. There is no per-frame cost, because `t()` runs when screens render.

## Architecture (Opus)
- `src/i18n.js`: gettext style, where the English text is the key. `t(text, vars)` takes `{name}` placeholders and falls back to English. Also `LANGS`, `pickLang(saved, prefs)`, `loadLang(code)` (dynamic `./locales/${code}.js`) and `translateDom(root)` (`data-i18n` / `data-i18n-html` / `data-i18n-title`).
- `src/boot.js` is the entry in `index.html`. It loads the language, translates the static HTML, then imports `main.js`. A promise chain is used instead of top-level await, because Vite 5's es2020 target has none.
- Settings: `lang` (`''` = browser). The modal shows native language names, and a change reloads the page.
- `src/locales/<code>.js` holds `export default { 'English text': 'translation' }`.

## Risks
- **Longer text:** German and French run 20–30% longer. Buttons, the HUD and touch labels need a check per language.
- **Upkeep:** every new UI string needs 7 translations. The coverage test (step 3) fails when one is missing.
- **Machine translation:** native speakers should review before promoting a language.
